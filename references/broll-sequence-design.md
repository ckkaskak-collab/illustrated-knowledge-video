# B-roll 段落设计与具体范例

用于新分镜、B-roll 制作及“画面空、像PPT、解释不清”等质量修订。先解决连续讲解如何让观众理解，再选择布局与动作。这里的范例是设计参照，不是渲染通过的模板；按本期内容选择，不强制套固定段数、镜头数或时长。

## 先组织段落，再拆单镜

通读已定稿内容，在现有九列表的“画面设计”和“动态变化”中写清以下信息。无需另建一套分镜表。

- **观众问题与本段结果：** 接住前面哪个疑问，看完能理解或判断什么。已有开场承诺与结尾相互对应；有完整配音时只设计视觉，不为补结构擅自增加案例、对白或改稿。
- **贯穿案例与证据：** 选能支持后续解释的具体对象，指出画面里哪处内容能证明当前关系；明确所需整体、局部、部件、版本或实际操作素材。简单清单可以直接呈现。
- **观看路径：** 按需要在成品、局部、原理图、并列比较、实际操作及整体结果之间转换。每次转换带来新的观察或理解，保留对象身份与上下文。
- **段落连接：** 本段留下什么对象、状态或未解问题供后面使用。方法类内容可在结尾用简化案例检验迁移，但仅在文案与授权支持时采用。

挑模板之前，应能用具体对象描述“看到了什么变化，因此明白什么”。若仍只能写“标题出现、卡片移动、强调结论”，继续补素材和解释设计。镜头卡、缓动和音效随后服务已成立的过程。

## 从参考作品学习什么

用户指定的两条本地参考：Xilo《零基础入门 Opus…》约5分09秒，一只桌子《和AI协作时，怎么把模糊的不满意变成具体…》约4分13秒。以下时间为观察区间，非逐帧切点。依据是覆盖全片的每2秒顺序画面、完整音轨ASR、部分密集帧与字幕核对；未完成连续播放听审，不据此指定缓动曲线、卡点或音效。

| 参考区间 | 可见组织方式 | 可迁移的设计方法 |
|---|---|---|
| Xilo 00:00–00:22，04:38–结尾 | 开场成品预览与学习路线，后面交付使用入口并返回成品 | 让成果先成为具体目标，解释结束后兑现承诺 |
| Xilo 00:46–01:02 | 翻页类比、巫师帧序列、代码与预览、采样、视频结果保持对应 | 同一内容跨表达形式，接通类比、机制与产物 |
| Xilo 01:12–01:56 | 像素案例由整体放大到像素格；界面案例逐层加入结构、样式与图形 | 尺度变化揭示机制，同一对象的层次变化解释构建 |
| Xilo 02:54–03:28 | 舞者源素材、去背景、舞台文字与分屏合成 | 先准备可分层素材，再演示加工；主体质感不必统一成图标 |
| 一只桌子 00:00–00:29 | 海报、模糊修改词、乱线与选择表现“不满意却说不清” | 画面可把问题和心理矛盾具体化；不据此擅改本项目A-roll方式 |
| 一只桌子 01:12–02:54 | 同一客厅经历问题定位、选择对象、局部修改、细节核查、保留或退回 | 案例持续积累状态，依据、决定与后果都可见 |
| 一只桌子 03:14–03:40 | 同一房间浅中深版本与对应裁片，选完整版本作为下一轮基准 | 局部帮助辨差异，整体帮助作判断；保留版本继承关系 |
| 一只桌子 03:40–结尾 | 新的几何图形案例复演方法，最后回应开头“可以”的含义 | 复盘检验方法迁移，收尾解决开头提出的问题 |

学这些组织方法，不直接复制作者角色、头像、素材或全片画风。参考中的提前总览、问号占位不覆盖本包[逐项出现规则](broll-editable.md#整组随口播出现)；概览显示到什么程度仍由已确认文案与口播锚点决定。

## 完整设计范例：从资料中回答问题

这是独立构造的教学示例，所有资料内容均为虚构；用于说明设计精度，不是用户定稿、真实政策或可直接套用的声音时间轴。

**讲解意图：** 先找到相关资料，再抽出有用内容形成可回查的答案。问题为“周五出差前，要完成哪些申请？”示例资料为：`doc-travel`“出发前提交出差申请，经主管审批”；`doc-meeting`“周五例会移至线上”；`doc-purchase`“采购设备需提交采购申请”。保留准确短句，不能用横线假字替代决定筛选的内容。

| 阶段 | 画面实际内容与变化 | 观众由此获得的理解 | 衔接与素材 |
|---|---|---|---|
| 提出任务 | 问题成为主对象；三份资料依对应口播出现，展示可辨标题与必要短句 | 当前要解决什么，候选内容是什么 | 保存问题与三个文档ID；按语音安排阅读量 |
| 呈现筛选依据 | 聚焦问题中的“出差”“申请”；定位出差制度的对应句。例会虽有“周五”、采购虽有“申请”，内容各不匹配本次任务，随讲解退到次要位置 | 选择依赖内容关系，单个词相同不够 | `doc-travel`保留原句；定稿未涉及反例时不额外加此论点 |
| 提取与组织 | 放大被选原句，对应显示两个独立要点：“提交出差申请”“主管审批”；要点进入答案区域，原句以小幅参照保留 | 答案具体来自资料中的哪些内容 | 两个要点各有源文档ID及对应片段；按口播出现 |
| 返回问题核查 | 问题与整理结果并置，依次定位每个要点对应原句；不增添资料未提供的时限或流程 | 结果回答了问题，也能回查依据 | 保留结果供下一段使用；需要时回到人物拿到文件的A-roll |

本段至少需要可读的问题、资料短句、两条抽取结果和来源对应。字号与布局随整体/局部任务调整；有配音时按原时长删减不必要展示，不通过塞满小字或伪造时间强行完成。资料不够支撑答案时，画面标明尚未解决的问题，不用勾号把缺口包装成成功。

**不充分的实现：** 四个纸张图标入场、三个消失、一个移到问题旁、弹出“精准回答”。它只能证明对象被移动，观众无法知道选择理由与答案内容。

**成立的实现：** 观众能指出相关句子、被抽出的要点及答案对应关系。动画可以简洁，结果也需要停留；不要求每个阶段都换场景或变形。

## 另外两种可适配的段落

**逐层构建：** 展示与当前内容对应的成品 → 进入同一个对象的基础结构 → 加入本段讲到的属性或部件 → 返回成品，定位新增部分。素材需有成立的各层状态；讲解UI时实际改变布局、样式和图形，不能只把HTML/CSS/SVG三个标签依次点亮。

**局部修改与判断：** 完整对象定位问题 → 抽出对应局部 → 改一个目标属性并保留约束 → 回到整体比较 → 按文案演示保留或退回。素材需有原版、修改版、同位置裁片；例如地毯纹样变化时保留透视和家具上下文，不能让版本同时改变灯光与布局却归因于纹样。

这些是关系范例，不强制所有镜头都包含失败分支、前后对比或完整闭环。挑与原稿知识任务一致的部分，具体素材与时间重新绑定。

## 用连续讲解段校准执行

已授权制作时，先实现一个能暴露本期主要难点的连续段，检查其素材、过程、结果与相邻镜头连接，再扩展同类做法。它是内部制作验证，不自动变成用户确认关卡。无音频只能验证布局和动作设计；维护skill时不额外启动配音、生图或渲染。

通过标准采用[叙事与动作检查](captions-and-delivery.md#叙事与动作检查)。解释证据不足就补素材或改设计；信息过密就减少同时阅读量、调整主次或拆分状态；动作生硬才进入动效细化。保存实际检查范围，未渲染的设计不能称为效果已达标。
